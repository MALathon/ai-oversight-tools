## Chunk 1: M1 — Foundation (Terminology + Artifacts)

### Task 1: Rename phase IDs and labels in all JSON data files

The most impactful change — ~3800 occurrences of "phase" in data files. This is mechanical find-and-replace but must be done carefully to avoid breaking the graph.

**Rename mapping:**
- `"phase-1"` → `"stage-1"`
- `"phase-2"` → `"stage-2"`
- `"phase-3"` → `"stage-3"`
- `"phases"` (array key in JSON) → `"stages"` (where it's a field name, NOT the top-level `phases.json` array key — see below)
- `phaseGuidance` → `stageGuidance`
- `phaseAppropriateness` → `stageAppropriateness`
- `phaseRelevance` → `stageRelevance`

**CRITICAL: Do NOT rename these:**
- "Phase I", "Phase II", "Phase III" clinical trial references — these are standard clinical trial phases (e.g., "Phase I clinical trial"), a completely different concept from the IRB review framework stages
- Any mention of "phase" in free-text descriptions that refers to clinical trial phases, drug development phases, or other domain-specific uses of "phase"
- Only rename the framework's structural IDs (`phase-1`, `phase-2`, `phase-3`), field names (`phaseGuidance`, etc.), and UI labels that refer to the Three-Stage Framework

**How to distinguish:** The framework uses hyphenated IDs (`phase-1`), camelCase field names (`phaseGuidance`), and UI labels like "Phase 1" / "P1". Clinical trial phases appear as "Phase I" (Roman numerals) or in prose like "clinical trial phase". When in doubt, check context — if it's about the IRB review framework, rename; if it's about a clinical trial or drug development lifecycle, leave it.

**Stage name updates (in `phases.json`, which we rename to `stages.json`):**
- Phase 1: "Discovery & Algorithm Development" → "Discovery & Ideation"
- Phase 2: "Validation (Prospective or Synthetic Validation)" → "Analytic & Performance Validation"
- Phase 3: "Clinical Investigation or Deployment" → "Real-World Deployment"
- Short names: "Discovery" stays, "Validation" stays, "Clinical/Deployment" → "Real-World Deployment"

### Task 7: Flip reviewer checklist voice from investigator-directed to IRB-directed

This is a systematic rewrite of every prompt in `reviewer-prompts.json`. The pattern:
- **Before (investigator):** "Please report the demographics of your training dataset..."
- **After (IRB):** "The protocol describes the demographics of the training dataset and notes any known gaps or limitations"

The IRB reviewer is checking whether the protocol addresses the issue, not telling the PI what to do.

**Files:**
- Modify: `webapp/static/data/reviewer-prompts.json`

- [ ] **Step 1: Rewrite all prompts to IRB-directed voice**

Go through every prompt in reviewer-prompts.json and rewrite from "Please describe/report/explain..." to "The protocol describes/reports/explains..." or "The protocol addresses..." or "The investigator has documented..."

Voice rules:
- Subject is "the protocol" or "the investigator", not "you"
- Tone is assessment/verification, not instruction
- Keep all CFR references and phase/stage assignments unchanged
